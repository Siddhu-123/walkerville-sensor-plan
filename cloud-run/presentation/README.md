# Client presentation: sewer sensor placement

Two pages over the same Simulation 2.5 results:

- **`index.html`, the story page** (present this). One map of Walkerville that never reloads: each scene is
  a camera move. Scenes 1 to 12 use the 2D top view (the answer, the problem, how we found it, the proof),
  13 to 18 tilt into 3D to explain each parameter, 19 to 21 return to the plan. Controls: arrow keys,
  space, scroll or swipe, the two arrows at bottom right, or click an act in the progress bar. `F` is
  full screen; `#scene-id` in the address opens a scene. Hover any manhole for its levels; on "Try it",
  click one to connect 150 homes there.
- **`deck.html`, the detailed deck** (below): every table and appendix, for questions and for print.

## What the story page claims, and how each claim is checked

| Claim | Where it comes from |
|---|---|
| The five sensors are the best five for the worst weather case | `build/prove_placement.py` solves the exact integer program (HiGHS) for 1 to 10 sensors; every optimum is proven, not time-limited |
| Phase 2 loses nothing | The best five additions to phase 1 reach the proven 10-sensor optimum exactly |
| It beats the obvious choices | Same scoring for the deepest-flow-today set, the individually most-exposed set and the best of 20 random sets |
| It holds on unseen weather, mostly | Leave-one-case-out with the same optimiser; the dry and storm cases drop, and the page says so |
| Each sensor's job | Each phase-1 sensor's share of dry, design-wet and storm growth on its own |

The greedy (one at a time) plan that the sandbox and `deck.html` show is up to 10 points worse than
the proven best in the worst case, so the story page recommends the optimum and shows greedy only for
comparison.

## Rebuild the story page

```
python presentation/build/export_scenario.py --check   # the 8,200-run tables (must print "reconciliation passed")
pip install pulp highspy                               # only prove_placement.py needs these
python presentation/build/prove_placement.py           # optimum, alternatives, held-out cases -> data/proof.json
python presentation/build/export_story.py              # 3D network, homes, responses, facts -> data/story.json
python presentation/build/check_copy.py --story        # every {{token}} in content/story.js resolves
node presentation/build/story_smoke.js [shots-folder]  # every scene at desktop and tablet sizes
```

`export_story.py` also reads the property connections in `../data/walkerville_inspection_prop.geojson`
(override with `OSP_DECK_HOUSES`) and needs `pyproj`. For SA Water's data, follow the steps below, run
the three builds against the private folder, and re-read every sentence in `content/story.js`: the
copy states Walkerville's findings (each sensor's job, which cases drop when held out), not constants.

# The detailed deck

An interactive slide deck on the Simulation 2.5 results. It runs in a browser with no server and no build
step. Sliders and charts respond live, and it prints to PDF. It is built from the Walkerville sample network
today. When SA Water's own network data arrives, the same steps re-run on that data and the deck updates.

## Open it

Open `deck.html` in a browser, or serve this folder. Keys: arrows, Page Up/Down and space move between
slides. Home and End jump to the first and last. The drop-down jumps to any slide, and `#n` in the address
bar opens slide `n`.

## Files

| Path | What it is |
|---|---|
| `index.html`, `assets/story.css`, `assets/story.js`, `content/story.js` | The story page: shell, styles, map engine and scene copy |
| `data/story.js`, `data/proof.js` | Generated by `export_story.py` and `prove_placement.py`. Do not edit by hand |
| `deck.html`, `assets/deck.css`, `assets/deck.js` | The deck shell, styles and the widgets (maps, charts, sliders, filters) |
| `content/slides.js` | The slide copy. Numbers are `{{fact}}` tokens, filled from the data |
| `data/scenario.js`, `geometry.js`, `config.js` | Generated by the export. Do not edit by hand |
| `data/source/` | The pinned Simulation 2.5 results used for Walkerville (see `SOURCE.md`) |
| `build/export_scenario.py` | Turns the results into every number the deck shows |
| `build/check_copy.py` | Fails if the copy uses a figure the export does not produce |
| `build/smoke_test.js` | Loads every slide in Chromium, checks for errors, overflow and working controls |

## Rebuild and check (Walkerville)

```
python presentation/build/export_scenario.py --check   # re-derive figures; must print "reconciliation passed"
python presentation/build/check_copy.py                # every token resolves
node presentation/build/smoke_test.js                   # needs playwright; CHROMIUM_PATH optional
```

`--check` recomputes the figures the sandbox page states (baseline counts, the worst-case and average
curves for the 150 mm alarm and the 25 mm rise, the spill counts and the random-set check) and fails if
any differ. It reproduces them exactly for Walkerville.

## When SA Water's data arrives

1. **Keep the data out of the repository.** SA Water network data must not be committed, pasted into any
   AI tool, or published. Do the build in a private folder:
   ```
   export OSP_DECK_SOURCE=/private/osp/source        # same layout as data/source/
   export OSP_DECK_OUT=/private/osp/deck/data        # generated files land here
   ```
   Copy `presentation/` to the private folder and build there. The repository keeps the Walkerville snapshot.
2. **Run the simulations on their network.** The grid is produced by the sandbox's `simulation_src/`
   (`sim25_grid.py`), with SA Water's network and settings in place of the public snapshot. Copy the
   resulting `summary.json` files into `OSP_DECK_SOURCE/grid_whole/<case>/`.
3. **Update the settings** that the grid used: alarm depth, rise thresholds, growth sizes, cases, sensor
   limit. They live in `config.js`, copied into the source folder.
4. **Run the export without the Walkerville check:**
   `python build/export_scenario.py --skip-reconcile`. It prints the figures. The findings check is for
   Walkerville only.
5. **Re-read every sentence in `content/slides.js`.** The copy states what Walkerville showed, for example
   "a fixed alarm misses most growth" and "the first few sensors do most of the work". Those are findings,
   not constants. Keep a sentence only if the new figures support it, and change or remove it if they do not.
6. **Check the sources.** Title slide, the parameter register and Appendix A3 name the Walkerville sample
   and its sources. Update them for the pilot.
7. Run `check_copy.py` and `smoke_test.js` against the private build.

Slides 1 to 9 and 17 to 18 are general: they use only the site and case counts. Slides 10 to 16 state
findings and must be re-read. Appendix A2 lists the checks.

## Known limits

- Printing gives about one page per slide. A slide taller than one page continues onto a second page.
- The worst-case curve rises in jumps, as the data shows. The slide says so.
- Layout-based placement rules are quoted from the sandbox page (0% in this test). They are not recomputed
  here, and the slide says so.
- Everything rests on steady-state simulations with assumed values. Slide 16 lists them.
